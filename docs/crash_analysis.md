# Crash Dump Analysis

IEDClient uses [Google Breakpad](https://chromium.googlesource.com/breakpad/breakpad) for automatic crash reporting. When the application crashes, a minidump (`.dmp`) file is saved automatically.

| Platform | Crash dump location |
|----------|-------------------|
| Linux    | `~/.local/share/IEDClient/crashes/` |
| Windows  | `%LOCALAPPDATA%\IEDClient\crashes\` |

## Prerequisites

Install the analysis tools via [Rust/Cargo](https://rustup.rs/):

```bash
cargo install minidump-stackwalk
cargo install dump_syms
```

These tools work on both Linux and Windows. Make sure the cargo bin directory is in your `PATH`:

| Platform | Path |
|----------|------|
| Linux    | `~/.cargo/bin` |
| Windows  | `%USERPROFILE%\.cargo\bin` |

## Analyzing a crash dump

### 1. Get the symbols archive

Download `IEDClient_syms_<version>.zip` from the GitHub release artifacts, or generate symbols locally.

**Linux:**
```bash
./ci/build_local.sh --release --symbols
# Produces: dist/IEDClient_syms_<version>.zip
```

**Windows (manual):**
```powershell
dump_syms.exe build\src\Release\IEDClient.exe > IEDClient.sym
# Or with PDB:
dump_syms.exe build\src\Release\IEDClient.pdb > IEDClient.sym
```

### 2. Extract symbols

**Linux:**
```bash
unzip IEDClient_syms_*.zip
# Creates: symbols/IEDClient/<BUILD_ID>/IEDClient.sym
```

**Windows:**
```powershell
Expand-Archive IEDClient_syms_*.zip -DestinationPath .
# Creates: symbols\IEDClient\<BUILD_ID>\IEDClient.sym
```

### 3. Decode the crash dump

**Linux:**
```bash
minidump-stackwalk ~/.local/share/IEDClient/crashes/<dump>.dmp symbols/
```

**Windows:**
```powershell
minidump-stackwalk.exe %LOCALAPPDATA%\IEDClient\crashes\<dump>.dmp symbols\
```

The output shows the full stack trace with function names, source files, and line numbers.

## Platform-specific details

### Linux

Breakpad installs signal handlers for `SIGSEGV`, `SIGABRT`, `SIGFPE`, `SIGBUS`, `SIGILL`. The crash handler runs in the crashed process with minimal code to write the minidump.

Symbol files are extracted from ELF binaries with DWARF debug info. The build must use `RelWithDebInfo` or `Debug` (the default release configuration already does this).

### Windows

Breakpad uses `SetUnhandledExceptionFilter` to catch access violations, stack overflows, and other unhandled exceptions. The crash handler writes a minidump using the Windows `MiniDumpWriteDump` API.

Symbols can be extracted from either:
- **PDB files** (`.pdb`) — generated by MSVC alongside the executable
- **PE executables** (`.exe`) — if built with debug info embedded

For MSVC builds, ensure `/Zi` (debug info) and `/DEBUG` (linker) flags are enabled. CMake's `RelWithDebInfo` sets these automatically.

**Note:** On Windows, the Breakpad `ExceptionHandler` constructor differs slightly:
```cpp
// Windows initialization
google_breakpad::ExceptionHandler eh(
    crashDir.toStdWString(),       // wide string path
    nullptr,                        // filter callback
    crashCallback,                  // minidump callback
    nullptr,                        // context
    google_breakpad::ExceptionHandler::HANDLER_ALL);
```

## Manual symbol generation

### Linux
```bash
dump_syms ./build/src/IEDClient > IEDClient.sym

head -1 IEDClient.sym
# MODULE Linux x86_64 <BUILD_ID> IEDClient

mkdir -p symbols/IEDClient/<BUILD_ID>/
cp IEDClient.sym symbols/IEDClient/<BUILD_ID>/IEDClient.sym
```

### Windows
```powershell
dump_syms.exe IEDClient.pdb > IEDClient.sym

# Read the first line for BUILD_ID
Get-Content IEDClient.sym -TotalCount 1
# MODULE windows x86_64 <BUILD_ID> IEDClient.pdb

mkdir symbols\IEDClient.pdb\<BUILD_ID>\
copy IEDClient.sym symbols\IEDClient.pdb\<BUILD_ID>\IEDClient.sym
```

**Note:** On Windows, the module name in the symbol directory includes the `.pdb` extension.

## What's in a crash dump

The minidump contains:
- CPU register values at crash time
- Thread stack memory
- Loaded module information with build IDs
- Crash signal (Linux) or exception code (Windows) and faulting address

It does **not** contain function names or source code — those come from the `.sym` symbol files, which are matched by build ID.

## Generating test crashes

### Linux
```bash
./dist/IEDClient-linux-x86_64.AppImage &
kill -SIGSEGV $(pidof IEDClient)
ls ~/.local/share/IEDClient/crashes/
```

### Windows
You can trigger a test crash by adding a null pointer dereference in the code, or use a debugger to force an exception. Check `%LOCALAPPDATA%\IEDClient\crashes\` for the dump file.
